## Factual claims not fully reproduced, and source checks

- 25 sessions, 2,329 calls and 1,056 reminders: my independent read-only Python transcript parser, folding subagents into parents and filtering sessions starting October 3 onward, found 26 sessions, 2,357 calls and 1,066 reminder attachments. I reproduced 22 graph calls and 17 mixed commands. Without a saved manifest and cutoff, the difference remains unresolved.
- 13% / 20% / 18% / 49% navigation attribution and 74/670 committed-file overlap: not independently reproduced. Reading `local/graphify-eval/usage_report.py` exposed additional limits: mixed query/search output is attributed wholesale to graph, and `Write` is included among “opened” files.
- Three planted defects detected: no preserved mutation-run artifact was present in `local/graphify-eval/results/`; its only file was the ordinary accuracy result.
- Questions written before any graph run: `local/graphify-eval/questions.json` states this, but that statement alone does not independently establish chronology.
- “Adopted after M2”: contradicted as a milestone boundary. `git show -s --format='%h %ad %s' --date=iso 516a393 6ffee35` places graph installation at 17:05:23, before M2 was ticked at 17:30:10 on October 3. M2 cannot simply be classified as an unexposed review without checking review timing.
- No app change between graph build and HEAD: confirmed by empty `git diff --stat de9d2cf 54d9806 -- app`. The M15/M16 tick hashes and October 10 reading-rule commit were also confirmed with `git show -s` and `git show a682078 --stat`.
- 13/18 retrieval and 10/10 affected: reproduced by independently recounting `local/graphify-eval/results/2026-10-10-54d9806.json`, not through a complete fresh query replay. The latter means ten importers across four symbol probes, not ten independent probes.
- Import coverage: independently parsed relative imports/exports/dynamic imports under `app/src`, `app/server` and `app/e2e`, resolved against source files, and compared file pairs to import relations in `app/graphify-out/graph.json`. Result: 766 expected TS pairs, all 766 present; 59 additional pairs explainable through a re-export hop; zero unexplained pairs under the scorer's scope.
- CSS and source coverage: independent source traversal counted 103 CSS import statements and 260 TS/TSX files; the graph had zero CSS source nodes and a node for every checked TS/TSX file.
- Call coverage: independently examined graph call relations against all seven saved questions and checked each question's source-evidence regex. C1–C4 had the expected targets; C5–C7 had no matching targets. All source-evidence regexes matched.
- Version and query behavior: `graphify --version` returned 0.9.74. A read-only `graphify query 'Where is the shared date formatting utility?'` returned source paths and a 2,000-token truncation warning, plus a warning about the old node-ID scheme. No suggested rebuild was executed.

## Overall recommendation

Required before execution: freeze the decision algorithm and corpus; normalize and isolate the arms; require D; define reproducible scoring and accuracy gates; measure complete costs and at least one implementation outcome; approve a capped budget covering every phase. Otherwise, label the work an orientation pilot and leave the keep/remove decision inconclusive.
